# Contexto del cambio

- Objetivo: cerrar fuente/identidad, cancelación y cuotas de generación con fuentes, sin perder las herramientas ya solicitadas ni permitir bypass HTTP tras rechazo nativo.
- Actor: Hub/Orbe registrados con sesión main. Navegador independiente conserva su transporte explícito; Electron deniega si falta/falla su puente.
- Alcance: contrato de datos JSON acotado y herramientas cerradas, servicio HTTP compartido main/web sin dependencias de Electron, handlers con trabajos/cancelación ligados a fuente/identidad, preload/wrapper y consumidores con unknown comprobado.
- No objetivos: retirar todas las claves VITE/SDK del renderer, acreditar disponibilidad real/modelos del proveedor, agregar herramientas locales ni resolver autorización de otras APIs.
- Restricciones: conservar índice ajeno y unidades previas; respaldos relativos contra unidad 40, sin credenciales/.env reales ni llamadas a modelos/cuentas reales. Código congelado durante compuerta/build. Mantener capas servicio/handler/preload/wrapper y sin dependencias nuevas.
- Contratos: generar conserva canal/entrada modelName/apiKey/body y agrega requestId para cancelación; canal cancelar ligado al emisor propio. google_search/url_context y code_execution existente bajo la política local de modelos. Cuerpo hasta 320000 bytes UTF-8, respuesta hasta 8 MiB, plazo 150 s, cuatro transportes concurrentes y uno por emisor, sin cola/retry de efectos.
- Riesgo: alto por clave/costo/datos privados. Fuente/sesión revalidadas tras esperas. Cancelar revoca HTTP; no permite cancelar otra ventana ni reutilizar ID activo. Slots retenidos mientras transporte físico no termine aunque ignore señal; no se promete retirar datos ya enviados. Errores fijos, sin key/texto del proveedor.
- Criterios: fuente ajena/subframe/sin sesión/revisión obsoleta no envía ni publica; Stop/cierre/A-B-A/navegación/timeout abortan transporte; cuotas cuentan bytes reales; no fallback HTTP en Electron tras rechazo/ausencia de canal; herramientas válidas se conservan, errores no filtran payload/key; tipos y pruebas dirigidas/completas sin deuda nueva.
- Incertidumbres: compatibilidad de modelos se rige por la política existente supportsCodeExecutionCombo, no por una consulta real del proveedor. El fallback de modelos/claves tras error de proveedor puede reenviar contexto: preservar comportamiento actual documentando ese límite, pero cortar tras rechazo de autoridad/busy/cancelación nativa.
