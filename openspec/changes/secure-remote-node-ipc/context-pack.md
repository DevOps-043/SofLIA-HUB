# Contexto del cambio

- Objetivo: cerrar los 13 canales Remote Node frente a emisor no confiable, entrada inválida, confirmación omitida, sesión obsoleta y cambio de destino durante aprobación/transporte.
- Actor: Hub/Orbe registrados con sesión main vigente. El runtime main/WhatsApp y el servidor entrante mantienen sus guardas existentes, sin recibir autoridad desde IPC.
- Alcance: contratos/quotas por operación, guarda nativa común, confirmación de mutaciones/acciones/capturas, revisión de configuración vinculada a main, cancelación y límites HTTP del cliente remoto, integración de inicio y pruebas de cuatro capas.
- No objetivos: cifrar almacén de nodos, resolver ownership multiusuario global, reescribir Computer Use/Desktop Agent ni acreditar RLS, CI o UI reales.
- Restricciones: conservar rama acumulativa con unidades previas sin guardar; respaldos relativos y hashes contra unidad 38. Sin secretos/.env, herramientas nativas, cuentas/red reales, stage/commit/push ni SQL. Mantener integración modular y una compuerta final con cobertura/build.
- Contratos afectados: mismos 13 canales y firmas válidas; entradas cerradas para campos consumidos, rechazo explícito de campos extra, sobres de fallo/cancelación/incierto tipados. Consultas de host rechazan con mensaje fijo para conservar DTO exitoso. AbortSignal es interno main, no IPC.
- Riesgo y HITL: alto. Fuente/identidad se valida antes y después de esperas; cambios de configuración invalidan la revisión. Confirmación nativa cancelar por defecto para configuración/registro/borrado, ejecución remota, cierre de proceso y captura. Ningún token en detalle o logs. Efectos ya enviados pueden ocurrir pese a cancelación; devolver incierto y no reintentar.
- Criterios verificables: los 13 canales niegan ausencia de sesión, ventana ajena, subframe/documento ajeno; rechazan payloads/tamaños/esquemas inválidos antes del servicio; cancelar/timeout/navegación/A-B-A/cambio de configuración impiden envío; HTTP acotado y cancelable no publica metadata tras invalidación; argumentos válidos y errores seguros cubiertos desde preload/allowlist/wrappers; sin deuda de lint nueva.
- Incertidumbres: almacenamiento sigue global y plano; no afirmar aislamiento entre usuarios ni cifrado. La configuración de red privada es funcionalidad intencional de emparejamiento, no un servicio de URLs arbitrarias: sólo HTTP(S) sin credenciales/query/fragmento, con destino revisado por el usuario. HTTP entrante y acciones runtime requieren auditoría posterior independiente.
