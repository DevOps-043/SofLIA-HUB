# Contexto del cambio

- Objetivo: cerrar autorización/contrato de documentos Python y respetar protección de datos en errores y lectores alternativos, manteniendo sidecar y consumidores internos.
- Evidencia: cinco pytools:* sin caller/schema; parse-document acepta ruta libre del renderer sin consumidor renderer de producción localizado; privacidad comunica éxito si falla persistencia; tablas conservan sheet sin redactar; DOCX puede recurrir a mammoth y contexto Office puede adjuntar imagen/UIA sin protección después de fallar el parser.
- Actores: ajustes/selección de documento en ventana principal; servicios main de escritorio/computer-use con sus permisos actuales. No ampliar agentes ni tratar una skill de desarrollo como herramienta runtime.
- Alcance: caller/actor/frame/documento/aridad; selector main con snapshot temporal estable de un archivo local admitido; cuotas/esquemas de salida; cancelación y cambios A/B/A/política antes/después de esperas; configuración de máquina validada y persistida sin falso éxito; inhibir fallback crudo cuando se exige redacción y redactar etiquetas de tabla.
- No objetivos: cifrado/propiedad por usuario de preferencias heredadas, RLS, OCR/redacción de imágenes, detección semántica completa de PII, certificación de parsers/antivirus o límites duros de CPU/RAM del SO. No instalar modelos/dependencias, usar documentos personales, leer .env, ejecutar SQL ni desplegar.
- Contratos: mismos cinco canales; BREAKING explícito de parseDocument renderer para seleccionar en main sin ruta recibida. La API main parseDocument(filePath,maxPages) y consumidores conservan entradas, con contexto opcional. No existe consumidor renderer de rutas que migrar.
- Límites propuestos: un selector/lectura renderer a la vez, un documento PDF/XLSX/XLSM/PPTX/DOCX de hasta 50 MiB; texto de entrada hasta 400000; salida Markdown hasta 400000, tablas/celdas/metadata acotadas, sin rutas/errores libres. No equivalen a validación completa de contenedores ni SLO.
- Privacidad: preferencia global de máquina, sin atribuir dueño al legado; ausencia inicial conserva opt-in=false, error/corrupción no se convierte silenciosamente en false. Enabling es reversible; deshabilitar protección requiere revisión nativa del efecto. Revisión y selección se invalidan al cambiar caller/sesión; activar la protección invalida lecturas antiguas. El detector por patrones puede omitir PII; UI explicará alcance real.
- Criterios: negativas antes de selector/sidecar/escritura; selección controlada no acepta paths renderer; copias verificadas/limpiadas sin borrar originales; errores de guardado no publican éxito; no entrega de lectura anterior a B ni política nueva; protección no recurre a raw/imagen en Office; pruebas TS/Python/UI/native y gate/build con evidencia.
- Baseline: unidad anterior verify:pr 5391 aprobadas, cinco omitidas. Baseline dirigido actual 84 casos en seis archivos (python-tools, sidecars y desktop-context). Se reutiliza rama codex/reduce-technical-debt y se preserva el worktree acumulado; sin concurrencia de agentes ni commits/publicación.
